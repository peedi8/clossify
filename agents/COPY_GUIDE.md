## 0. 상위 제약 (이걸 어기는 작법은 금지) — 하이브리드([[COMPLIANCE_RULES]] §4)
- **제목=기능/키워드(감성 금지), 본문=감성 허용.** 인테리어/소품은 감성구매라 본문은 무드로 욕망 자극 OK.
- **단 AI슬롭 클리셰 금지**: "OO을 담은", "고요 속 은은한 빛", "일상에 특별함을" 같은 닳고 막연한 표현 ❌. **신선·구체·상품맥락**의 감성은 환영(예: "흙과 불이 남긴 손맛", "비움이 주는 단정함").
- **가짜 통계/과장 금지**: 재구매율·판매량 등 **수치 지어내기 금지**([[COMPLIANCE_RULES]] §1·정직). 실제 스펙만 수치화. **모르면 과장 금지** — 소스에 없는 사실은 쓰지 않는다(작가 입력 규칙).
- **정품/공식/최고/1위 금지**([[COMPLIANCE_RULES]] §1).
- **외국어(한자·외래어) 상품 어휘는 순한글로 풀어 쓴다**: 찻잔 받침, 차 트레이, 단위는 cm 환산 표기. 사용자가 입력한 한국어 상품명·라벨을 그대로 사용하되 의미가 모호하면 자연스러운 한국어 명칭으로 정리. 출력 전체(제목·본문·제안 필드)는 한국어를 우선한다.
→ 아래 공식은 위 제약 안에서 적용. 본문은 감성+기능 섞어 쓴다.

## 1. 오프닝 훅 — "첫 3줄이 승부" (모바일)
- 첫 줄은 **상황·질문**으로. `이 제품은~`으로 시작 금지.
- 단 우리는 **막연 감성 금지** → 질문은 *구체적 사용맥락*으로:
  - ✅ "좁은 책상 위, 식물 둘 자리가 마땅찮으셨죠?"
  - ❌ "당신의 일상에 특별한 무드를…"(막연)
- 첫 화면(고정헤더 다음 첫 섹션) = 핵심 혜택 한 줄 + 베스트 상품컷([[COMPLIANCE_RULES]] §13).

## 2. 문제 → 공감 → 해결 (3단)
- **문제**(구체 상황) → **공감**(그래서 불편했죠) → **해결**(이 상품이 이렇게).
- 예: "잔가지 하나 꽂을 작은 화병이 없으셨죠 → 큰 화병은 부담스럽고 → 7.5cm 미니 화병이 딱 그 자리를 채웁니다."

## 3. 스펙 → 혜택 (수치화, 단 실제값만)
- 모든 사양에 "그래서 좋은 점" 한 줄([[COMPLIANCE_RULES]] §13). **실측 수치만** 사용:
  - ✅ "무게 약 120g — 한 손에 가볍게", "높이 7.5cm — 모니터 옆에도"
  - ❌ "구매자 92%가 만족"(가짜통계 금지)
- 단위·구체 숫자가 신뢰를 만든다(실제값 한정).

## 4. Before / After (해당될 때)
- 변화가 보이는 카테고리(수납·정리·인테리어)면 전후 대비:
  - "빈 책상 모서리 → 작은 식물 하나로 분위기 포인트."
- 단 과장된 변화 묘사 금지(실제 용도 범위 내).

## 5. 톤 ({STORE_NAME})
- 차분한 셀렉트샵. 친근하되 들뜨지 않게. 기능·활용 중심 + 위 훅/3단 구조로 읽히게.
- DETAIL 섹션: `짧은 소제목(혜택)` + `2~3문장(기능+활용+실측)`.

### 5.5 필드별 레지스터 (사용자 캘리브레이션 — "전부 팩트면 안 어울림")
| 필드 | 온도 | 규칙 |
|---|---|---|
| hero, dark_title/dark_body, **cap1/cap2** | **감성(무드)** | 상품이 놓인 삶의 장면·감각을 그리는 브랜딩 문장. **스펙·치수 숫자 금지.** 클리셰 금지는 유지 — 구체적 장면 감성만("흙과 불이 남긴 손맛" 계열) |
| lead | 브릿지 | 무드에서 안내로 넘어가는 한 문장 |
| tips, features | **기능·활용** | 관리법·용도·소재 팩트는 여기로. **치수/사이즈 숫자는 상세 카피 전체 금지** — 치수는 옵션 카드 소관(사용자 결정) |
- 근거: 감성 자리(캡션·밴드)에 스펙을 쓰면 상세페이지가 설명서처럼 읽힘(실검수).
  반대로 tips/features에 무드를 쓰면 정보가 사라짐. 자리마다 온도를 지킨다.
- 치수 금지 근거: 사이즈는 하단 옵션 카드가 옵션별로 정확히 표시함 — 본문에 또 쓰면 중복+틀릴 위험만.

## 6. SEO 연동
- 제목은 [[naming_agent]]·[[COMPLIANCE_RULES]] §7(검색량 기반). 본문에도 상위 검색키워드를 **자연스럽게**(도배 금지) 녹임([[COMPLIANCE_RULES]] §13).

## 7. 작가 파이프라인 계약 (LLM=작가, Python=검수관)
- **LLM이 쓴다, Python은 검사만**: 근거 추출·금칙어·카테고리/상품 일치·길이/형식 검사. 파이썬이 문장 조립 금지.
- **QA 실패 = 재작성**(규칙 덧대기 아님): 더 좋은 입력카드를 주고 다시 쓰게 한다. 복수 후보 생성 → QA가 선택.
- **source_identity_card 선행**: 제품핵심명·카테고리·소재·형태·용도·금지어·유지할 명사 카드를 먼저 만들고, 생성은 카드 기반으로만.
- **OCR 선행 원칙**: "AIO는 글자를 지우지만, 카피 작가는 지우기 전의 글자를 보고 써야 함" — 이미지 속 치수/재질/구성은 제거 전에 상품 사실 패킷으로 보존해 작가 입력에 포함.
- **2단계 카피**: ① 초안(이미지 편집 전, 원본정보 기준 — 정체성·SEO 제목·핵심 장점·카테고리 판단용) ② 최종(이미지 슬롯 확정 후 실제 상세 문장).
- **렌더 게이트(text_teacher_contract)**: 작가 계약(정체성·SEO 상품명·카테고리·태그·카피) 없이 렌더 금지. 카피 선검수(no-detail 프로브)는 가능하되 카피 PASS ≠ 등록 가능(제목 게이트 별도).

## 8. 슬롯 글자수 제한 (템플릿 카피)
- `hero_title` ≤18자 / `section_heading` ≤12자 / `body` ≤45자×2줄. 초과 시 재작성 — 카피라이터는 "칸 크기 안에 맞춰 쓰는" 역할.
- 이미지 역할 태그(hero/material/size/scene/option/detail_cut) → 블록별 카피 매핑(첫인상/질감과 마감/공간 활용/옵션 선택).
- 템플릿 고정 문구(p6band, OPTION GUIDE 밴드 등)는 카피 슬롯이 아님 — 검수·성공/실패 판정에서 제외.

## 9. 카테고리별 카피 앵글 (living table — 신규 카테고리마다 누적)
| 카테고리 | 앵글 |
|---|---|
| 화병 | 배치·오브제 활용·세척/물때 |
| 벽지 | 부착 전 먼지 제거·표면 확인·공간 확장감·시공 주의 |
| 조명 | 밆기 분위기·침실/거실 용도·전구/전원 주의 |
| 찻잔 | 용량·손잡이감·세척·선물/다도 분위기 |

## 7.5 2단계 카피 실배선
- **초안 카피**(슬롯 미확정): 텍스트(사용자 입력·사실 패킷) 기반 — 정체성·카테고리 판단용.
- **최종 카피**(슬롯 7/7 확정 후에만): 작가가 확정 슬롯 이미지 7장을 **직접 보고** 씀 —
  hero/lead는 히어로 이미지에 보이는 장면에서 출발, cap1/cap2는 해당 슬롯 사진 묘사.
  보이는 것만 말하고 수치는 사실 패킷의 실측만(이미지로 추정 금지).
- **역방향 옵션 규칙**: 창작 카피는 옵션명을 나열/인용하지 않는다(옵션 안내는 하단 옵션 카드 소관).
  단 제품 호칭은 확정 옵션명 어휘와 어긋나지 않게(어휘 드리프트 금지).

## 10. 옵션명은 카피가 아니다
- 옵션 작가 = **충실한 라벨러**(카피라이터 ❌). 옵션 raw에 없는 용도·검색어(`사무실`·`생일선물`·`머그컵`) 추가 금지, **옵션별 차이만** 표기.
  - ✅ `둔황 둔둔컵 3종세트 선물상자` / `무금테 전자레인지 가능`
- 옵션 카드 표시명 = 최종 `optionName1`과 반드시 일치 (예쁜 이름 별도 창작 금지).
- LLM 처리가 옵션 간 차이를 뭉개면 버리고 로컬 사전 fallback. 코드형 옵션(MDYZ01 등)은 명칭 문제가 아니라 이미지 매핑 문제.
