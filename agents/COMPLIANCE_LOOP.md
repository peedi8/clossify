# 절대규칙 자가개선 루프 (Compliance Self-Improvement Loop)

> 목적: 상품을 많이 퍼올수록 **미처 못 본 변수**가 계속 나온다. 그걸 *우회로 덮지 말고* 근원을 연구해 [[COMPLIANCE_RULES]](단일 진실원천)에 접어넣어, 다음 상품부터는 자동으로 막히게 한다.
> 이 문서 = 그 루프의 *형식*. 규칙 자체는 COMPLIANCE_RULES.md, 발생한 변수 기록은 RULE_GAPS.md.

---

## 0. 3개 문서의 역할 (헷갈리지 말 것)
| 문서 | 역할 | 갱신 시점 |
|---|---|---|
| **COMPLIANCE_RULES.md** | 절대규칙 = 단일 진실원천(SSoT). 코드/에이전트가 참조하는 *현재 확정 규칙*. | 변수가 규칙으로 승격될 때만 |
| **RULE_GAPS.md** | 변수 원장(append-only). 등록 중 튀어나온 *아직 규칙 아닌 케이스* + 근원연구 + 해결. | 새 변수 나올 때마다 |
| **COMPLIANCE_LOOP.md** (이 문서) | 변수→규칙 승격 *절차*. 누가 뭘 하고 무슨 증거로 닫는지. | 거의 안 바뀜 |

---

## 1. 표준 루프 (한 상품 등록 = 한 사이클)
```
소싱(URL)
  → prepare (번역·가격·이미지·카피·카테고리·고시 자동생성)
  → QA 게이트 (qa_image · qa_copy · qa_compliance, fail-closed)
       ├─ 전부 PASS/WARN  → 사용자 검토 → 승인 시 register(실게시)
       └─ FAIL 또는 "규칙에 없는 새 변수"  → §2 변수 처리로
```
- **QA는 항상 fail-closed**: FAIL이면 config 무관 register 차단. WARN은 통과(보고).
- **register(실게시)는 항상 사용자 명시 승인** — 자동 푸시 금지.

## 2. 변수 처리 — *우회 금지, 근원 연구* (★핵심)
QA가 잡았거나 사람이 눈으로 발견한 "규칙에 없던 케이스"가 나오면:

1. **RULE_GAPS.md에 먼저 적는다** (변수 ID·증상·증거 이미지/필드). *고치기 전에 기록* — 무음 처리 금지.
2. **근원 연구 (Resolver 역할)**: 왜 통과했나? 어느 단계가 놓쳤나? 픽셀 휴리스틱 한계인가 / 규칙 공백인가 / 코드 버그인가.
3. **우회 유혹을 명시적으로 거부**: 드롭·회색마스크·스킵·기본값으로 숨기기 = *해결처럼 보이지만 품질 저하*. GAP 항목에 "거부한 우회 + 채택한 근원수정"을 *둘 다* 적는다.
4. **수정 (Builder 역할)**: 최소 안전수정. 규칙 공백이면 → COMPLIANCE_RULES.md에 한 줄 추가 *그리고* 코드 체크 구현(규칙만 적고 코드 안 짜면 무의미).
5. **벤더분리 적대검증**: 내가 짠 수정을 *외부 모델/감리자가 공격*. "이 수정이 다른 상품을 깨뜨리나? 필드/시그니처 실존? 과적합?" 같은 모델 자기검토 = 편향이라 금지.
6. **증거로 닫는다**: 실패했던 케이스 재실행 → PASS 출력. 유닛테스트 통과 수. *주장 아닌 관측가능 증거*로만 GAP을 CLOSED 처리.

## 3. 무엇을 자동 고치고(묻지 말고) 무엇에 멈추나
**자동 (활성기능 자기유발 결함 = 실행이지 결정이 아님):**
- 빈·무효 산출 / 출력계약 깨짐 / 스키마 불일치 / 쓰레기 이미지 통과 / 스케일 위반 / 중국어 잔존 / 중복 블록 / 고시 빈칸.

**멈추고 사용자에게 (정책·방향 결정):**
- 새 금지어·새 카테고리 정책 / 기본값 OFF→ON / 새 외부 의존성 / 파괴적 파일작업 / 가격·마진 정책 / **register 실게시** / 복수의 유효한 정책 중 택1.

## 4. 한 상품 통과 게이트 (절대규칙 체크리스트 = 등록 전 필수)
register 직전 이 14항이 전부 PASS여야 한다 (QA 게이트가 기계검사, 사람은 검토):
- [ ] §1 금지어 0 (정품/100%/최고/1위…) — 제목·본문·이미지
- [ ] §2 상세 본문 단일컬럼 (HTML 코드검사)
- [ ] §3 이미지: 제품 keep·중국어 0·쓰레기(비석/프로모/스펙표) 제외·스케일밴드[600~920]·작은원본<360 스킵
- [ ] §3 상세 이미지 **MIN 5 / MAX 10** (못 채우면 옵션이미지 끌어와 채움)
- [ ] §4 카피: 제목=기능 / 본문=감성허용 but 빈마케팅·가짜통계 0
- [ ] §5 옵션: 번호매칭·중국어만 번역·품절반영
- [ ] §6 헤더/푸터 상수 (카테고리 subtitle 오염 0)
- [ ] §7 SEO 제목: 코히어런트 키워드구(앞가중)·카테고리 relevance·오카테고리 스펙용어 0
- [ ] §7 sellerTags 관련 키워드 (노이즈 0)
- [ ] §8/§12 원산지=**중국**(필드)·KC 면제(OVERSEAS)·카테고리=정확 leaf
- [ ] §10 폰트 모바일 기준(본문 35~40px)
- [ ] §11 통짜 금지(3000px↑ 분할)
- [ ] §12 고시 7필드 채움·교환반품 5요소
- [ ] §13 첫 화면 3초 안에 "뭘 파는지"

## 5. 증거 정직성 (안 한 건 PASS 아님)
- 정적 코드검사 ≠ 런타임 정확. 이미지 스케일·쓰레기 판별은 *실 렌더*로 확인.
- 안 돌린 체크는 "not verified" 명기. 픽셀 휴리스틱이 못 잡는 건(비석 vs 화병) **vision-QA가 최종 판정** — 로컬 규칙은 빠른 1차 필터일 뿐.
- 변수 처리에 캡·샘플링·휴리스틱 경계를 두면 *무엇이 빠졌는지* GAP에 명시.
