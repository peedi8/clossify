# ADR-0002: 로컬 MCP 서버 + BYO-key

- **상태**: 승인
- **날짜**: 2026-08-01

## 배경

원격 호스팅 모델은 서버 비용·과금 인프라·그리고 치명적으로 **셀러의 커머스 자격증명이 운영자 서버를 경유**하는 신뢰 문제를 만든다. 텍스트 추론(상품명·SEO·고시·카피)은 사용자가 이미 보유한 MCP 클라이언트의 LLM이 수행할 수 있다.

## 결정

1. **배포 형태 = 로컬 MCP 서버(stdio).** 운영자 서버는 존재하지 않는다. 자격증명은 사용자 PC의 설정 파일에만 존재한다.
2. **텍스트 추론은 클라이언트 LLM이 담당.** 서버는 도구(fetch/build/prepare/register/verify)와 런타임 프롬프트 자산만 제공한다. sampling 의존은 피하고, 오케스트레이션 자체를 클라이언트 LLM에 맡긴다.
3. **결정론적 검증은 서버 코드에 남긴다.** QA 3분할(이미지/카피/컴플라이언스)과 등록 게이트는 fail-closed — 클라이언트 LLM이 관대해도 서버가 막는다.
4. **이미지 생성 = BYO-key 어댑터.** 외부 이미지 API 키는 선택 사항이며, 키가 없으면 해당 단계만 우아하게 스킵된다. 외부 생성물(타 MCP 포함)도 attach 경로로 투입 가능하되 동일 QA 게이트를 통과해야 한다.
5. **장시간 작업은 잡 패턴**(start → status 폴링)으로 노출한다. MCP 도구 호출 타임아웃과 분 단위 파이프라인의 불일치를 흡수한다.

## 결과

- 운영자 고정비 0. 사용자 비용 = 자기 LLM 구독 + 선택적 이미지 API 사용량.
- 네이버 커머스/검색광고 API는 셀러 본인 발급분을 사용 — 자격증명 수탁 없음.
