# Clossify — 중간 보고서

**네이버 스마트스토어 상품 자동등록 로컬 MCP 서버**

작성일 2026-08-28 · 상태 **개발 중(pre-release)**

---

## 0. 이 문서의 성격

**미완성 상태에서 쓴 보고서다.** 완료를 주장하지 않는다.
되는 것·되다 만 것·아직 없는 것을 구분해 적었고, 각 주장에는 그것을 어떻게
확인했는지를 함께 적었다. 확인하지 못한 것은 확인하지 못했다고 적었다.

---

## 1. 무엇을 만들고 있나

판매자가 사진과 최소 정보를 주면, **규정 검사를 통과한 것만** 스마트스토어에
등록되게 하는 로컬 도구다. 서버 호스트가 없고 자격증명은 사용자 PC 에만 있다.

```
상품 자료 → 상세페이지 생성 → 상품정보제공고시 작성 → 규정 검사 → 등록 → 조회 재검증
```

### 왜 만드나

스마트스토어 상품 등록에서 **상품정보제공고시**는 36개 상품군마다 필수 항목이 다르고,
법정 문구·규제 신고값이 섞여 있다. 잘못 신고하면 판매자 책임이다.
그런데 그 검사는 등록 버튼을 누른 뒤에야 알 수 있고, 실패해도 무엇이 왜 부족한지
알기 어렵다. 이 도구는 **등록 전에 기계가 먼저 검사**하고, 부족하면 무엇이 왜
부족한지 말한다.

---

## 2. 지금까지 확인된 것

### 2.1 실제 등록이 관통했다 (2026-08-28)

MCP 호출 → 실등록 → 조회 재검증이 **처음으로 끝까지 돌았다.**
판매중지 상태로 올려 노출은 0이며, 저장된 고시 본문이 보낸 값과 일치함을 조회로 확인했다.

**한계**: 표본 **1건**이다. 카테고리·상품군별 재현은 아직 하지 않았다.
"한 번 됐다"이지 "항상 된다"가 아니다.

### 2.2 관통 과정에서 결함 6건이 드러났다

관통을 시도하기 전에는 **하나도 보이지 않던 것들**이다. 단위 테스트와 정적 검사는
전부 통과하고 있었다.

| 결함 | 성격 |
|---|---|
| 필수 항목 검사가 중첩된 고시 본문을 읽지 못함 | 값이 있는데 없다고 판정 |
| 미룬 항목을 기록·조회할 수 없음 | 판매자가 무엇을 미뤘는지 알 방법이 없었음 |
| 조립기 두 곳의 입력 규약이 서로 다름 | 한쪽만 값을 받음 |
| 상품군별 항목이 입력에서 본문으로 가는 통로가 없음 | 값이 통째로 버려짐 |
| 참조 데이터가 원본 목록의 일부를 잃은 채 생성됨 | **19개 상품군 영향** |
| 과거 기록의 결론이 범위를 잃은 채 굳어 있었음 | 다른 항목을 보고 내린 결론 |

**다섯 번째가 가장 크다.** 필수 항목 목록이 원본 API 응답에서 일부 누락된 채
만들어져 있었고, 그 결과 가전·아동용품·의료기기·자동차용품 등 **19개 상품군은
등록 자체가 실패**했을 것이다. 실패 이유도 알 수 없었다 — 플랫폼이 돌려주는
오류 상세를 사용자에게 전달하지 않았기 때문이다.

이 결함은 **API 를 실제로 호출해야만** 드러난다.

### 2.3 되는 것

- MCP 도구 11개 (설정 점검 · 이미지 업로드 · 등록 준비 · 등록 · 조회 · 상태 변경 등)
- 36개 상품군별 고시 필수 항목 검사 (미충족 시 등록 차단)
- 법적 금지 표현 차단 · 근거 없는 가격 주장 거부
- 고시 항목 **의도적 미루기** 선언과 그 기록
- 이미지 입력 정규화 (로컬 파일 / 외부 URL / 업로드된 CDN URL)
- 등록 전 미리보기 승인 · 등록 후 목록 조회 · 판매 상태 변경
- 자동 시험 **2,347건 통과**

## 3. 설계에서 지킨 것

### 조용한 자동 채움 금지

규제 신고값을 코드가 지어내지 않는다. 값이 없으면 **싣지 않고 검사가 지적한다.**

실제 사례 — 원래 이 도구는 **상품명을 잘라 품명(규제 신고값)에 넣고** 있었다.
상품명은 마케팅 문구이고 품명은 규제 신고값이므로, 그대로 두면 마케팅 문구가
규제 필드로 잘못 신고된다. 자동 채움을 걷어내고 **명시 입력만 받도록** 바꿨다.
판매자 입력이 한 칸 늘어나지만 잘못 신고하는 것보다 낫다.

### 검사를 통과해야만 산출이 나온다

검증되지 않은 파일은 애초에 만들어지지 않는다. 화면이 안 바뀌면 성공일 수 없다.

### 실패는 성공과 구별되게 표면화한다

"됐다"는 주장 대신 관측 가능한 증거로만 완료를 선언한다.
플랫폼이 돌려주는 오류 상세를 사용자에게 그대로 전달한다(비밀값은 가린 채).

## 4. 아직 없는 것

| 항목 | 상태 |
|---|---|
| 상품군·카테고리별 등록 재현 | 표본 1건뿐 |
| 상품명 SEO 완전체 | 근거 있는 재료 생성까지. **검색량·경쟁도 기반 키워드 우선순위는 없다** |
| 배송비·A/S·고시 템플릿 코드 연동 | 값으로 조립 중. 판매자가 화면에서 만든 템플릿과 따로 논다 |
| 필수 항목 판정의 근거 | 플랫폼 API 가 필수 여부를 알려주지 않는다. 현재 판정은 **우리 가정**이다 |
| 대량 등록(엑셀) 경로 | 설계 전 |
| 사용 가능한 릴리스 | 없음 |

**네 번째 항목을 특히 밝혀둔다.** 상품군 정의 API 응답에는 각 항목이 필수인지
표시가 없다. 우리가 "목록에 있으면 필수"로 가정해 검사하고 있으며,
그 가정이 맞는지는 등록을 시도해 플랫폼이 거부하는지로만 알 수 있다.

## 5. 기술적으로 남은 것

아래는 **법인 조건이 정해진 뒤에** 이어갈 항목이다. 지금 확정하면 되돌릴 위험이 있다.

1. **재현** — 다른 상품군으로 등록을 한 번 더 관통한다. 표본 1건은 증거가 약하다.
2. **템플릿 연동** — 판매자가 화면에서 만든 템플릿을 코드로 참조한다.
   지금처럼 값을 매번 조립하면 화면 설정과 어긋난다.
3. **상품명 SEO 상위 계층** — 키워드 우선순위·글자수 압축·최종 확정.
   검색 데이터 경로가 막혀 있어 대안을 찾아야 한다.

## 6. 다음 단계는 법인 설립이다

**여기서 기능을 더 만드는 것보다 법인을 먼저 세우는 것이 맞다고 판단한다.**
지금 더 만들어도 법인 설립 후 조건이 달라지면 **다시 만들어야 하기 때문**이다.

구체적으로 아래가 법인 여부에 따라 달라진다.

**1. 배포 경로가 자격에 걸린다**

네이버 커머스 API 를 제3자에게 제공하는 경로는 두 가지인데, 그중 `API대행사` 는
**국내 법인 사업자가 필수**다(개인·해외 사업자는 반려). 나머지 하나인 `커머스솔루션` 은
자격 제한이 없지만 **사업자 서버에서 호출하는 구조**라 지금 같은 로컬 실행 도구는
해당하지 않는다.

즉 이 도구를 **나 외의 판매자에게 제공하려면** 법인이 전제다. 그 구조를 모르는 채로
배포·인증·과금 계층을 만들면 경로가 정해진 뒤 대부분 다시 만들게 된다.

**2. 판매자 정보가 규제 신고값으로 상품에 실린다**

제조사·A/S 책임자·연락처 같은 값이 상품정보제공고시에 **그대로 신고**된다.
지금은 개인 명의로 들어간다. 법인이 되면 이 값들이 전부 바뀌고,
이미 등록된 상품의 신고값도 갱신 대상이 된다.
템플릿·기본값 설계를 지금 굳히면 그때 다시 손봐야 한다.

**3. 저작권자·라이선스 주체가 바뀐다**

현재 저작권자는 개인 명의다. 법인 설립 후에는 저작권자와 기여자 동의서(CLA)의
주체가 달라진다. 라이선스 구조를 지금 확정해도 다시 정리하게 된다.

**4. 계정·자격증명의 귀속이 바뀐다**

스토어와 API 자격증명이 개인 계정에 묶여 있다. 법인 이관 시 인증·권한 구조가
달라지므로, 그 위에 얹는 다계정·위임 설계는 지금 만들 이유가 없다.

---

**그래서 다음 순서는 이렇다.**

1. 법인 설립
2. 배포 경로 확정 (`API대행사` / `커머스솔루션` 중 어느 쪽인지)
3. 그 경로가 요구하는 구조에 맞춰 인증·배포 계층 설계
4. 그 다음에 기능 확장

**지금 단계에서 더 쌓는 것은 되돌릴 가능성이 높은 작업이다.**
현재 상태를 여기서 고정하고, 법인 조건이 정해진 뒤 이어간다.

## 7. 정직하게 남기는 것

- 이 보고서의 **모든 수치는 실측**이다. 시험 통과 수, 결함 수, 등록 건수 모두
  실행 결과에서 가져왔다.
- 관통 검증은 **한 번** 성공했다. 반복 성공을 주장하지 않는다.
- 결함 6건은 **고쳤지만**, 같은 종류가 더 없다고 말할 근거는 없다.
  드러난 방식(실제 호출)을 보면 더 있을 가능성이 높다.
- 릴리스 가능한 상태가 아니다.
