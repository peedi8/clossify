# 조립 결과 문서(scene) 형식

이 문서는 상세 페이지 조립 결과의 **구조적 표현** 형식을 정의한다. 상세 페이지
렌더러가 HTML 문자열을 만들 때 사용하는 섹션 구조를 문서로 함께 내보내면, 편집
도구가 이를 읽어 조각 단위 수정을 할 수 있다. 즉, 이 문서는 조립 결과의 구조적
표현이며, 편집 도구가 이를 읽어 조각 단위 수정을 할 수 있도록 공개한다. 문서 하나만
읽고도 형식을 완전히 이해할 수 있도록 작성되었다.

## 최상위 구조

| 키             | 타입     | 의미                                                                       |
|----------------|----------|----------------------------------------------------------------------------|
| `version`      | 문자열   | 형식 버전. 현재 값은 `clossify-scene-v1` 이다. 하위호환 검사에 사용된다.  |
| `generatedAt`  | 문자열   | 생성 시각(ISO 8601, UTC). 결정론 검사에서는 제외 대상이다.                 |
| `canvas`       | 객체     | 렌더 폭 등 캔버스 메타데이터.                                              |
| `sections`     | 배열     | 섹션 객체 리스트. 순서는 렌더 순서와 동일하다.                             |
| `provenance`   | 객체     | 문서의 출처 표시. `origin`, `renderer` 키를 가진다.                        |

### `canvas`

| 키         | 타입   | 의미                                  |
|------------|--------|---------------------------------------|
| `widthPx`  | 정수   | 렌더 폭(픽셀). 상수에서 읽는 고정값.  |

### `provenance`

| 키         | 타입   | 의미                                                                            |
|------------|--------|---------------------------------------------------------------------------------|
| `origin`   | 문자열 | 문서가 어떻게 만들어졌는지. `composed` 이면 조립(assemble)으로 생성됨을 뜻한다. |
| `renderer` | 문자열 | 렌더러 식별자.                                                                  |

`origin` 값이 `composed` 인 문서는 사용자가 제공한 입력을 조립한 결과이지,
임의로 값을 지어낸 것이 아님을 나타낸다.

## 섹션 객체

모든 섹션 객체는 공통 키 `id`, `kind` 를 가진다. `kind` 에 따라 추가 키가
달라진다.

### 공통 키

| 키     | 타입   | 의미                                                                                         |
|--------|--------|----------------------------------------------------------------------------------------------|
| `id`   | 문자열 | 섹션 식별자. 안정적이다(같은 입력이면 같은 `id`). 조각 단위 수정 지목에 사용한다.            |
| `kind` | 문자열 | 섹션 종류. `images`, `text`, `table` 중 하나.                                                |

### `kind: "images"`

이미지 갤러리 섹션(히어로 이미지 등).

| 키       | 타입     | 의미                                            |
|----------|----------|-------------------------------------------------|
| `images` | 문자열 배열 | CDN URL 리스트. 첫 번째가 대표 이미지이다.      |

### `kind: "text"`

텍스트 블록 섹션(도입부 상품명/요약 등).

| 키       | 타입   | 의미                                  |
|----------|--------|---------------------------------------|
| `blocks` | 배열   | 텍스트 블록 객체 리스트.              |

#### 텍스트 블록 객체

| 키      | 타입   | 의미                                                                               |
|---------|--------|------------------------------------------------------------------------------------|
| `id`    | 문자열 | 블록 식별자(예: `intro.title`). 안정적이다.                                        |
| `text`  | 문자열 | 블록 텍스트. 빈 값일 수 있다(사용자가 제공하지 않은 경우).                         |
| `source`| 객체   | 이 값이 어느 입력 필드에서 왔는지. 아래 `source` 규칙 참조.                        |

### `kind: "table"`

표 형태 섹션(스펙, 옵션, 고시/안내 등).

| 키     | 타입 | 의미                       |
|--------|------|----------------------------|
| `rows` | 배열 | 행(row) 객체 리스트.       |

#### 행(row) 객체

| 키       | 타입   | 의미                                                                   |
|----------|--------|------------------------------------------------------------------------|
| `id`     | 문자열 | 행 식별자(예: `specs.소재`). 안정적이다.                               |
| `label`  | 문자열 | 행 라벨(표의 왼쪽 열).                                                 |
| `value`  | 문자열 | 행 값(표의 오른쪽 열). 빈 값일 수 있다(사용자가 제공하지 않은 경우).   |
| `price`  | 문자열 | 옵션 섹션 행에만 존재. 가격 텍스트.                                    |
| `source` | 객체   | 이 값이 어느 입력 필드에서 왔는지. 아래 `source` 규칙 참조.            |

## `source` 규칙

각 텍스트 블록과 행에는 `source` 객체가 붙는다. 이 객체는 해당 값이 **어느 입력
필드에서 왔는지**를 문서 자체가 증명하게 한다. 값을 지어내지 않았음을 추적 가능하게
만드는 장치이다.

| 키        | 타입    | 의미                                                                                |
|-----------|---------|-------------------------------------------------------------------------------------|
| `field`   | 문자열  | 입력 필드 경로(예: `name`, `notice.wear.material`, `props.소재`, `options[1]`).     |
| `missing` | 부울    | 사용자가 이 값을 제공하지 않았으면 `true`. 이때 `value` 는 빈 문자열(`""`)이다.    |
| `verified`| 부울    | 값이 사용자 제공 입력에서 검증되었으면 `true`(선택 키, 있을 때만 의미를 가진다).    |

### `missing` 의 의미

사용자가 제공하지 않아 비어 있는 항목은 **생략하지 않고** `value: ""` 와
`source.missing: true` 로 표시한다. 이는 "빈 값" 과 "항목 자체가 없음" 을 구분하기
위함이다. 편집 도구는 `missing: true` 인 조각을 사용자 입력으로 채울 수 있다.

### 고시(notice) 섹션의 필드 분해 규칙

고시 본문이 중첩 dict/list 면 **파이썬 객체를 문자열화해 한 행에 넣지 않고** 각 leaf
필드마다 한 행으로 펼친다(조각 단위 수정이 가능하려면 필드별 행이 필요하다).

평탄화 예시 — 입력이 다음과 같을 때:

```json
{"notice": {"wear": {"material": "면 100%", "color": "아이보리", "size": "어깨42"}}}
```

scene 의 notice 섹션 행(분해 후):

```json
[
  {"id": "notice_material", "label": "material", "value": "면 100%",
   "source": {"field": "notice.wear.material", "verified": true}},
  {"id": "notice_color", "label": "color", "value": "아이보리",
   "source": {"field": "notice.wear.color", "verified": true}},
  {"id": "notice_size", "label": "size", "value": "어깨42",
   "source": {"field": "notice.wear.size", "verified": true}}
]
```

주의: 어떤 행의 `value` 도 `{` 로 시작하지 않는다(객체 문자열화 0건).

라벨은 **지어내지 않는다**. 한국어 라벨(예: `소재`)로 매핑할 근거가 없으면 필드명
(`material`)을 그대로 `label` 로 사용한다. 매핑 테이블이 도입되면 별도 티켓에서
반영한다.

### 고시 필수 필드 누락 표시 규칙

`data/notice_types.json` 의 해당 고시 타입 **필수 필드 목록** 중 사용자가 주지 않은
것은 `value: ""` + `source.missing: true` 로 **행을 남긴다**(생략하지 않는다).
필수 목록에 없는 임의 필드를 만들어내지는 않는다.

예시 — WEAR 타입에서 `material` 을 주지 않은 경우:

```json
[
  {"id": "notice_color", "label": "color", "value": "블랙",
   "source": {"field": "notice.wear.color", "verified": true}},
  {"id": "notice_material", "label": "material", "value": "",
   "source": {"field": "notice.wear.material", "missing": true}},
  ...
]
```

`missing` 으로 표시된 필드 집합은 `data/notice_types.json` 의 해당 타입 필수 필드
중 미제공분과 정확히 일치한다.

## 식별자(`id`) 안정성 규칙

모든 `id` 는 **안정적**이다 — 같은 입력으로 문서를 다시 만들면 같은 `id` 가 나온다.
이 성질은 나중에 "이 조각만 바꾸고 싶다" 고 특정 조각을 지목할 수 있게 한다.

안정성 규칙:

1. `id` 에 무작위값·생성 시각·프로세스 ID 가 들어가지 않는다.
2. `id` 는 입력 필드명·라벨·인덱스 등 입력에서 결정되는 값으로만 만든다.
3. 따라서 같은 입력에 대해서는 항상 같은 `id` 리스트가 나온다.

예시:

- `hero` — 히어로 섹션(항상 고정).
- `intro` — 도입부 섹션(항상 고정).
- `intro.title` — 도입부 상품명 블록.
- `specs` — 스펙 섹션(항상 고정).
- `specs.소재` — 스펙 행. 라벨이 `소재` 인 행의 식별자.
- `options_1` — 옵션 섹션 첫 번째 행.
- `notice_material` — 고시 섹션에서 라벨이 `material` 인 행(WEAR 타입 분해 후).
- `notice_returnCostReason` — WEAR 필수 필드 중 미제공인 `returnCostReason` 행.

## 결정론

같은 입력으로 문서를 두 번 만들면, `generatedAt`(생성 시각) 을 제외하고 **완전히
동일**하다. `generatedAt` 만 시각에 의존하고, 나머지 모든 키(특히 모든 `id`)는
입력만으로 결정된다.

## 섹션 순서

`sections` 배열의 순서는 렌더 순서와 동일하다:

1. `hero` — 히어로 이미지.
2. `intro` — 도입부(상품명/요약).
3. `specs` — 스펙/속성 표.
4. `options` — 옵션 표.
5. `notice` — 고시/안내 표.

각 섹션은 항상 배열에 존재한다. 내용이 비어 있어도(예: 이미지 0장) 섹션 객체 자체는
남고, 해당 섹션의 리스트(`images`, `blocks`, `rows`)는 빈 배열이 된다.
